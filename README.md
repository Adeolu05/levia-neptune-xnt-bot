# Neptune Privacy Community Bot

Levia is a Telegram bot for the Neptune Privacy (XNT) community.

## Commands

| Command                       | What it shows                                                                                                             | Source                      |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| `/hashrate` (alias `/stats`)  | 7-day hashrate chart, hashrate with 24h and 7d change, difficulty and block height                                        | NeptuneScan API             |
| `/price` (alias `/marketcap`) | 7-day price chart, price with 24h and 7d change, circulating supply, market cap, exchange buttons                         | CoinGecko + NeptuneScan     |
| `/mining`                     | How to start mining, with links to `xnt-gpu-miner` and `xnt-core`                                                         | Static                      |
| `/links`                      | Resources banner with buttons for the website, explorer, guides, news, Neptune Wallet apps, community channels and GitHub | Static (matches neptune.io) |
| `/start`, `/help`, `/about`   | Onboarding                                                                                                                | Static                      |

Replies use Telegram HTML formatting. Charts are drawn as SVG and rendered to
PNG with [`@resvg/resvg-js`](https://github.com/yisibl/resvg-js) using the
bundled Inter font (`assets/fonts`, SIL Open Font License), so rendering does
not depend on fonts installed on the host or on any third-party chart service.
`/start` sends a welcome banner built from the official Neptune Privacy logo
(`assets/brand/neptune-logo.svg`, from `https://neptune.io/neptunelogo.svg`).

Complete replies are cached for 3 minutes; if a source fails, the reply shows
what is available, marks the rest `n/a`, and is retried after 20 seconds. See
[`docs/data-sources.md`](docs/data-sources.md) for exactly how each value is
obtained and what has been verified.

## Requirements

- Node.js 22 or newer (Node.js LTS recommended)
- A Telegram bot token created with BotFather for local development

## Local development

1. Install dependencies:

   ```powershell
   npm install
   ```

2. Copy `.env.example` to `.env` and replace the placeholder with the token
   generated by BotFather. The application loads `.env` automatically.

3. Start long polling:

   ```powershell
   npm run dev
   ```

The bot registers its command menu with Telegram at startup. No real Telegram
connection is included in automated tests; use a disposable development token if
you perform a manual smoke test.

## Deploying to Railway

The bot uses Telegram long polling, so it needs no domain, HTTPS or open
port, just one always-on process. [`railway.json`](railway.json) tells Railway
to run `npm run build`, start with `npm start`, and restart on failure.

1. Create a project at [railway.com](https://railway.com), choose **Deploy from
   GitHub repo**, and select this repository.
2. In the service's **Variables**, add `TELEGRAM_BOT_TOKEN` (required). Optional:
   `LOG_LEVEL` (`info` by default) and `NEPTUNE_API_BASE_URL`.
3. Deploy. The logs should show `Telegram commands registered` and
   `Bot started with long polling`.
4. Stop any local `npm run dev` that uses the same token. Only one process can
   poll a bot at a time.

Every push to `main` redeploys automatically. During a redeploy the new
instance waits and retries for up to a minute while the old one shuts down,
instead of crashing on Telegram's polling conflict (HTTP 409).

Run a single instance (one replica). Never commit `.env`; if a token is ever
exposed, revoke it with BotFather and update the Railway variable.

## Project boundaries

The bot is read-only. It does not handle wallets, keys or transactions, and it
does not publish emission schedules or tokenomics that have not been verified
against the live network.
